#+title: Safety specification
#+startup: showall

*Status: draft of 2026-10-19, for the owner's acceptance.*  Nothing here
is in force until accepted; a rule changed or struck out by the owner is
changed here first, and the code and tests follow.

* What this is
What this configuration may and may not do with the owner's notes,
files, data and accounts -- written to be judged without reading the
code.  For each rule: what guards it in the code today, and which
automatic test shows it holds, or "none yet".  A rule without a test is
a promise in a comment, not a checked fact.

A test counts only when it has been shown to fail with the safeguard
taken out (recorded in CHANGELOG.md).  Tests run at every push
(=.github/workflows/checks.yml=) and by hand with =bash hooks/check-all=.

How this list was made: by searching the code (2026-10-19) for what
publishes, deletes, moves, reaches the network and runs programs, and
reading each place found.  A place the search patterns missed is not
here; the independent review (last section) is the check on that.

* Findings to decide
- *F1*: a note that git does not track is deleted for good
  (=delete-file=); a tracked one can be got back from git.  Proposal:
  untracked notes go to the trash.
- *F2*: the upload question (1.5) says where to, not that the upload
  makes the server folder an exact copy of the build (=rsync --delete=):
  a wrong =:remote= would empty that folder.  Proposal: the question
  says so, and refuses a =:remote= that is a home folder or =/=.
- *F3*: a theme installed with =git clone= takes whatever its
  repository holds that day.  Proposal: a commit recorded with the URL
  and checked out after the clone, as the Geekdoc archive has its
  SHA-256.
- *F4*: packages are not pinned (no lockfile), so a changed or
  compromised package would arrive with the next install.  Proposal: a
  lockfile, an established tool for it, decided separately (BACKLOG).
