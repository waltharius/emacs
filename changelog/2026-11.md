## Session 2026-11-18a — Automatic commits as a switch

### Why

A user of the configuration who does not use git kept receiving the
warning "Work that is NOT on the server: ... changes not
committed / The commit failed" for a writing project in `~/projects/`.
The project had become a git repository at creation
(428-writing-projects.el runs `git init`), and the commits there failed.
Nothing in the settings could stop the automatic commits: only the
exit question (`my/auto-commit-confirm-exit`) and pushing
(`my/auto-commit-push`) had options, and turning pushing off is itself
reported, by design.

### What — 207-git.el

- `my/auto-commit-mode`: a global minor mode, on by default, in the
  Git settings group (`C-c n , ,` → Tools → Git).  It starts and takes
  back everything 207-git did by itself at load: the idle timer, the
  start-up pull on `after-init-hook`, the exit commit on
  `kill-emacs-hook`, the exit question on `kill-emacs-query-functions`,
  the cycle when the last client frame of a daemon closes, and the two
  pieces of advice on `save-buffers-kill-emacs` (`my/auto-commit--new-quit`,
  `my/auto-commit--save-before-quit`).  The saved position is applied
  once the module has loaded, as every switch does.
- `my/auto-commit--arm-timer` starts the timer only with the switch on;
  a change of `my/auto-commit-idle-seconds` with the switch off starts
  nothing.  `my/auto-commit--on-idle` and
  `my/auto-commit--on-last-client-frame` check the switch too.
- Turning it off forgets what was already reported
  (`my/auto-commit--reported`), so that turning it on again reports
  pending work afresh.
- `my/auto-commit-status` (`C-c v ?`) says first that the automatic
  commits are off; the repositories follow.
- The warning about work not on the server ends with how to turn the
  switch off.
- `my/auto-commit--message-before-quit` stays outside the switch, now
  at advice depth -50: the order of the three pieces of advice stays
  what it was when all were added at load (new attempt, question about
  an open commit message, saving), whatever the switch does later.
- tests/test-auto-commit.el: 6 tests -- everything taken back when off
  and present once when on again, the timer staying off, the reported
  list forgotten, `C-c v ?`, `C-c v a` still committing on request, the
  warning naming the switch.
- function_helper.org (`#auto-commit-switch`, and a line in "A module's
  switch"), README.md (the 207-git row), TESTPLAN.org R59.

### Decisions

- A switch for the automatic part, not for the module.  207-git stays a
  core module with Magit and the `C-c v` keys, which act only when
  asked.  So the switch is not the module's `MyPKS-Switch`, and it is
  named after what it switches (`my/auto-commit-mode`) rather than
  after the module (`my/git-mode`): the weekly switch test would rightly
  find the `C-c v` keys still bound with a module switch off.
- Making 207-git an optional module, turned off in `C-c n , m`, was
  considered and not done: it would take Magit and the manual commit
  keys away with the automatic commits, and nothing in the request
  asked for that.
- `C-c v a` still commits when the switch is off: a command pressed is
  a request, and a machine that commits by hand may want exactly that.
- No question at turning it off.  Off loses nothing that is already
  committed, and the working tree stays as it is; the next start or
  `C-c v a` picks up from there.

## Session 2026-11-15a — The place of a journal day

### Why

The owner asked to record, in a journal note, the town or towns the day
was spent in: one key in the Insert menu, the places used so far offered
in the order of last visit, the first few chosen by typing a number, and
a place used for the first time simply typed.

### What — 000-core.el

- `my/note-keyword-remove`: takes the whole `#+keyword:` line away,
  newline included.  Writing an empty value is not the same thing:
  `my/note-keyword` reads an empty value as absent, but the line stays
  in the file and in every diff.
- `my/note-keyword-set` takes an optional column; the value is then
  aligned there, as Denote aligns its own front matter
  (`my/note-front-matter-column`, 14).  Without it a value still follows
  a single space, so the appearance keywords of existing notes keep the
  format they carry.  Both go through `my/note-keyword--line`, so the
  line a new keyword gets and the line a changed one gets cannot drift
  apart.
- 644-image-display.el: its `declare-function` follows the new arglist;
  the weekly declarations check caught the mismatch.
- tests/test-note-keywords.el: 11 tests of the keyword functions, which
  had none of their own.

### What — 405c-journal-places.el

- New module (optional, switch `my/journal-places-mode`), one command:
  `my/journal-set-place`, `C-c n i g`.  It asks for one place after
  another and writes them into the front matter as
  `#+place:      Kraków; Roma, Włochy`.
- The value: places separated by `my/journal-place-separator` ("; ").
  Not a comma, which belongs inside one place, between a town and its
  country.  `my/journal-place-home-country` ("Polska") is stripped when
  typed, so one town cannot stand in the list twice, bare and with the
  country; spelling, case and diacritics are kept.
- The candidates: derived from the notes, never stored.  The journal
  silo is scanned for `#+place:`, the first four kilobytes of each file
  (as `my/denote--file-title` reads a title), and each place is ranked
  by the newest journal day it appears on -- so the list is the order of
  last visit.  Cached for the session; a prefix argument scans again,
  and a place just written is added to the cache without one.
- Choosing: the first nine candidates are shown behind a number, and
  typing the number alone chooses at once.  `RET` on the empty first
  prompt changes nothing, `-` removes the keyword, and nothing is
  written before the last prompt is answered, so `C-g` leaves the file
  byte-identical.
- init.el, 208-keybindings.el (the menu tree), README.md, MODULES.org,
  TESTING.org (50 of 60 modules named by a test), TESTPLAN.org R56,
  function_helper.org (`#fn-my-journal-set-place`, and the Insert menu's
  list of entries other modules append).
- tests/test-journal-places.el: 28 tests -- the value format, the scan
  and its order, the numbered candidates, and every path through the
  command with the prompt stubbed.

### Decisions

- A front-matter keyword, not a property drawer, for the reason given in
  405b-journal-metrics.el: Org parses a file-level drawer only above
  `#+title:`, where it fights Denote's front matter, and a drawer under a
  headline duplicated the metrics block in practice.
- A module of its own rather than a field of 405b: a metrics field is a
  prompt with a fixed list of values, while a place needs a list
  derived from the notes, an order of last visit and more than one value
  per day.  Either module can be off without the other; neither touches
  the other's keywords (`my/journal--write-metrics` writes only the keys
  of `my/journal-metrics-keyword-order`).
- The keyword functions of 000-core.el are used rather than a regexp of
  the module's own: two mechanisms for one format is how the old
  `:well-being:` drawer came to be readable by eye and by nothing else.
  They were extended rather than copied (see above).
- The order comes from the notes, not from the minibuffer history:
  `savehist-mode` is not on here, and a scan of the notes also survives a
  restart and is the same on every machine.  Rejected with it: keeping a
  list of places in the settings or the collection, which would be a
  derived fact stored twice and free to drift from the notes.
- The numbers are the mechanism of flyspell-correct's completing-read
  interface, which the owner already uses for spelling (`C-;`): the
  index is a prefix of the candidate and a hook leaves the minibuffer
  when the whole input is one.  The digit is deliberately not bound to a
  key -- it has to stay typable.  Rejected: `vertico-indexed`, which
  selects with a prefix argument (`M-2 RET`) and not with a bare digit;
  a transient of its own, which would not search.  Its private function
  is not called: a package's `--` function is not an interface.
- Nine numbered candidates at most: a two-digit index is no longer one
  keypress, which is the whole point.
- Journal notes only, and only the journal silo scanned: where a day was
  spent is a fact about a day.  The command refuses elsewhere rather
  than writing a keyword nothing reads.
- `#+schema:` is not raised: the schema version describes the metrics
  set, and a place is not one of its fields.
- The group is named `my/journal-place`, not `my/journal-places`, which
  is the name of the function listing them; one symbol cannot be both
  (442-obsidian-import.el renamed its group for the same reason).

### Tested

`hooks/check-all` in the container: every test file passes, including
the two new ones (39 tests); `hooks/lint.py` all checks; the compile
check 0 failed, with no warning from either changed file; the
declarations check clean apart from packages missing here.  Emacs 29.3,

## Session 2026-11-13g — Capital letter at sentence start while typing

### Why

The owner asked for what a word processor does: the first word of a
sentence and of a paragraph gets its capital letter while typing,
built from an established package rather than from scratch, without
side effects elsewhere; and for a list of abbreviations ("np.",
"tzn.") after which it does not happen, with commands to add and
remove one.

### What

- New module 304-sentence-capitals.el (optional, off on a new machine,
  switch `my/sentence-capitals-mode`).  captain (GNU ELPA) does the
  typing; the module gives it, buffer-locally in Org buffers, the
  predicate (paragraphs and headline titles, not inside links, code,
  verbatim, timestamps, citations, tables, blocks, keywords, drawers)
  and the sentence start (Emacs's sentence motion with one space after
  a full stop, narrowed to the paragraph or title; not after an
  abbreviation, one letter, an ordinal of one to three digits or
  I/V/X, an ellipsis).  Options `my/sentence-capitals-in-lists` and
  `my/sentence-capitals-in-headings`.
- Abbreviations: a built-in Polish and English list and the owner's
  file `<settings folder>/dictionaries/sentence-abbreviations`
  ("abbr." adds, "-abbr." takes a built-in one out), read again when
  it changes on disk.  Commands `my/sentence-capitals-add-abbreviation`
  and `my/sentence-capitals-remove-abbreviation`; the file written in
  one step (`my/write-region-atomically`).
- Menu: a Capitals column first in Tools (`C-c n t`): `c` this buffer
  only, `+` add, `-` remove; it comes and goes with the switch.
- 000-core.el: `my/git-merge-by-union`, the merge=union line in
  .gitattributes, moved from 303-spelling.el
  (`my/spell--dictionary-gitattributes` now calls it), so both lists in
  the settings folder share it; it writes in one step too.
- init.el, MODULES.org, README.md, the ownership map, tests/ci-packages.el
  (captain), function_helper.org (`#sentence-capitals`,
  `#menu-capitals`, `#fn-my-git-merge-by-union`), TESTPLAN.org R58.
- tests/test-sentence-capitals.el: 18 tests, typing through
  `self-insert-command`, and `my/git-merge-by-union` (moved there from
  test-spelling-dictionary, which now checks the dictionary is handed
  to it); test-safety: 303-spelling off the list of modules calling
  `write-region`.

### Decisions

- captain rather than writing the hook: it is small, on GNU ELPA, and
  delegates exactly the two decisions that differ for Org through
  buffer-local functions, so nothing of it is patched or advised.
  Emacs has nothing built in.
- Org only: in Markdown, commit messages and code the rules differ, and
  an unwanted capital is worse than a missing one.
- No capital after an ellipsis or a short number with a full stop: in
  Polish both are as often inside a sentence as at its end.  Four
  digits (a year) end a sentence.
- Ordinary words that also end sentences are left out of the built-in
  list ("im.", "red.", "art.", "no.", "min."): a missing entry costs a
  shift key, a wrong one an undo.
- The owner's list in the settings folder beside the personal
  dictionary, not in Customize: Customize saves per machine
  (`hosts/<host>/custom.el`), the list is meant for all of them.
- Lighter " Captain" kept in the mode line: it says why letters change.

### Tested

`tests/test-sentence-capitals.el` 18 tests and
`tests/test-spelling-dictionary.el` pass (Emacs 31.1, captain 1.0.3);
`hooks/check-all`, the declarations check, `hooks/lint.py`.

## Session 2026-11-13f — #+language: as a code: new notes, existing notes, references

### Why

Org reads `#+language:` as a note's export language and expects a
code ("pl").  The template of bibliographic notes wrote BibLaTeX's
langid there ("polish"; 2026-11-13e, "Not changed"), and Zotero's
Language field brings other names ("pol", "pl-PL", "polski").  With
them an export gets English words and citeproc's en-US locale, and
`C-c x S` in such a note joined authors with "and".  The owner asked
for every such name to become the code.

### What

- 000-core.el: `my/language-code` (section NOTE KEYWORDS): a code with
  a region gives its language part; the babel, polyglossia and English
  names of Org's `org-latex-language-alist` and a short list of others
  (`my/language--other-names`: ISO 639-2, Polish and native names)
  give their code; anything else nil.
- 417-bibliography.el: the template's `#+language:` is
  `%^{mypks:language}`, filled with the code of the entry's language as
  citeproc reads it (`my/bibliographic-note--language`).
  `my/reference--locale` reads a note's `#+language:` through
  `my/language-code`, so `S` and `R` render in Polish in notes still
  saying "polish".
- 826b-maintenance-repairs.el: `my/maintenance-language-codes`, `C` in
  the repairs column of the Maintenance menu (`C-c n !`): lists in
  `*Language codes*` every value it would change and those it does not
  know, asks once, then writes only the value; a note with unsaved
  changes in a buffer is skipped and named.
- Tests: test-maintenance (the names, the list and the question, a body
  line and alignment untouched, an unsaved buffer skipped);
  test-references (the new note's code, a note saying "polish",
  "pl-PL" or "polski" rendered in Polish).
- function_helper.org: "Language codes" (`#language-codes`), the
  menu row, the front-matter section; MODULES.org: 826b.

### Decisions

- The code is the language alone, two letters: `en-GB` gives `en`.
  Org's dictionary of export words is keyed by the language, and
  citeproc looks a locale up by its file name, which "en-gb" does not
  match; British forms are lost for an `en-GB` note, which no note here
  has been seen to need.
- Org's own table rather than a list of our own for the 90 languages
  it knows: LaTeX export uses it, so the names it accepts are the names
  notes can carry.
- One question for the whole repair, after the list, rather than one
  per note as the keyword rename asks: the change is mechanical and the
  list shows it entirely; values it does not know are listed, not
  guessed.
- Key `C`: `L` is the package copies' (149-packages).
- The language of a new note is read through citeproc, which already
  turns langid into "pl-PL", from the same files as the names; citar
  only when citeproc cannot read the entry.

### Tested

`tests/test-maintenance.el` 19 tests and `tests/test-references.el` 20
tests pass (Emacs 31.1); `hooks/check-all` passes; the declarations
check, `hooks/lint.py`.

## Session 2026-11-13e — Names in a new bibliographic note as C-c x S writes them

### Why

A note made with `C-c x n` (citar-denote, template `biblio`) had its
front matter filled with the raw BibLaTeX fields: "#+authors: Block,
Fred L. and Somers, Margaret R.", the translators likewise, and
"#+year: %^{year}" for an entry with a date and no year field
(citar-denote leaves a placeholder it cannot fill as typed).  Since
2026-10-25 the short reference (`C-c x S`) renders names properly;
the owner asked for the note to read the same way.

### What

- 417-bibliography.el: the template's authors, translators and year
  are `%^{mypks:authors}`, `%^{mypks:translators}`, `%^{mypks:year}`,
  which citar-denote does not fill.  `my/bibliographic-note-fill`
  renders them with citeproc -- "Fred L. Block i Margaret R. Somers",
  editors "(red.)", the year of a full date -- and empties any
  placeholder left in a `#+keyword:` line.  It runs as `:after` advice
  on `citar-denote--expand-citation-macros`.  Options:
  `my/bibliographic-note-language` ("pl"),
  `my/bibliographic-note-fields-style`.
- `my/reference--locale-override`: a language a caller binds for
  `my/reference-render`, ahead of the note's `#+language:`.
- csl/styles/mypks-note-fields.csl: the configuration's own style;
  authors or editors, translators and year, separated by "‖".
- tests/test-references.el: five tests (names and year, English,
  editors and no translator, the raw fallback, through citar-denote's
  own expansion with the advice).  An entry with translators in the
  test bibliography.
- function_helper.org: "n — the front matter of a new bibliographic
  note" (`#bibliographic-note-front-matter`); csl/README.md.

### Decisions

- Advice on an internal function of citar-denote: it has no hook after
  filling a note, and its macros take only raw fields.  The function
  vanishing is caught by a test (citar-denote is installed for the
  push's tests), and would show in a note as visible placeholders, not
  as wrong data.
- One CSL style with three parts split on "‖" rather than three styles:
  literal text at the top of the layout is always printed, so there are
  always three parts, and the names are rendered by the same code as
  the short reference.
- The language is an option, "pl", not the note's `#+language:`: the
  template fills that line with the entry's BibLaTeX language
  ("polish"), which is no CSL locale (citeproc fell back to en-US and
  wrote "and"), and `org-export-default-language` is not set in this
  configuration (English).  The headings of the template are Polish, so
  the note's language is.
- On failure (citeproc missing, a key not yet in the .bib) the raw
  fields are written: making the note matters more than its format.

### Tested

`tests/test-references.el`: 19 tests pass (Emacs 31.1).  The module
compiles without warnings; the declarations check, `hooks/lint.py`
and `hooks/check-all` for references, bibliography and zotero pass.

### Not changed

- `#+language: polish`: Org reads `#+language:` as the note's export
  language and expects a code ("pl"); with "polish" an exported
  bibliographic note gets English words and the en-US citation locale.
  Left for the owner to decide.

## Session 2026-11-13d — Short reference between = signs (C-c x S)

### Why

The journal's font (Playpen Sans) has no italic.  A short reference
inserted with `C-c n t z S` / `C-c x S` -- Given Family, /Title/ (Year)
-- then reads as one run of text: the title cannot be told from the
authors, nor the reference from the sentence.  Between = signs, Org
shows it in the face of verbatim text, a font of its own, and, as the
owner checked in his notes, still shows the /title/ in italic inside it.

### What

- 417-bibliography.el: `my/reference-short-verbatim` (on by default,
  among the bibliography's settings): in Org, each short reference is
  inserted between = signs, `=Fred L. Block i Margaret R. Somers, /Karl
  Polanyi: .../ (2020)=`; several chosen at once, each its own pair,
  joined by "; ".  Outside Org nothing is added.  `my/reference-render`
  takes an optional WRAP, a function applied to each reference before
  they are joined; `my/reference--insert` passes it.
- tests/test-references.el: the option on and off, Org parsing the
  inserted text as one verbatim object; several keys and the text
  outside Org with the option on.
- function_helper.org (#reference-as-text): the example, a paragraph
  and the option.

### Decisions

- The whole reference, not the title alone: the owner's choice, from a
  note in which he had wrapped one by hand.
- The short reference only: the full one (`R`) is the entry of an
  exported bibliography and stays as the export writes it.
- On by default: the command is for notes that stay plain text (its
  section in function_helper.org says so); exported, verbatim text
  comes out monospaced with the title's slashes, which the option's
  documentation says.
- Each reference its own pair rather than one pair round all: "; "
  between them stays ordinary text.

### Tested

`tests/test-references.el`: 14 tests pass (Emacs 31.1).

## Session 2026-11-13c — Declarations checked at every push, for the packages installed

### Why

A wrong `declare-function` for citar (2026-11-03c) failed only the
weekly run, a week after the patch (2026-11-13a): the declarations check
ran only in hooks/check-weekly, because a declaration naming a
package's file needs that package installed.  But the push's CI
installs the packages the tests load (`tests/ci-packages.el`, citar
among them), and a working machine has every package.

### What

- tests/weekly/declarations.el: `my/check-declarations-installed`, the
  same check with a package's file that is not found skipped and
  counted ("N skipped (package not installed)").  A module's file is
  never skipped.  The "gone" report of exceptions is left out there (an
  exception's package may not be installed).
- The weekly check is stricter: `check-declare-ext-errors` on, so an
  "ext:" file not found fails too.  Until now check-declare skipped
  those silently, and a package that renamed a file declared "ext:"
  went unnoticed even with every package installed.
- hooks/check-all: the installed-only check after lint and the hook
  tests, in the "checks:" block; it fails the run on a problem.
- hooks/HOOKS-README.md: check-all and the weekly row.

### Decisions

- Skip rather than fail on a missing package: check-all runs on
  machines and CI jobs with only some packages, and a missing package
  is not a fault of the code.  Weekly keeps the strict check.
- Module files are never skipped: modules are always in the repository,
  so "file not found" for one is a misspelt or moved module.
- The skip keys on check-declare's reason "file not found", not on the
  "ext:" prefix: the modules mix both ways of naming a package's file
  (`"citar"`, `"ext:citar"`), and both are skipped alike when absent.

### Tested

Run with every package installed: 0 problems, 0 skipped.  With no
package installed: 0 problems, 8 skipped.  With the declaration of
2026-11-03c put back (`(&rest args)`): fails, "citar-select-ref
declared in citar.el: arglist mismatch".  A declaration naming a
misspelt module with no package installed: fails, "file not found".
Weekly with `check-declare-ext-errors` on and every package
installed: 0 problems, 1 excused.  `hooks/check-all` passes (Emacs
31.1); shellcheck passes on the three hook scripts.

### Lessons learned

- The lesson of 2026-11-13a ("run `check-weekly declarations` before
  delivering a declaration") is now automatic for the packages
  installed: `hooks/check-all` runs it.

## Session 2026-11-13b — Notes rewritten in one step (SAFETY 2.10)

### Why

The outside review of 2026-11-05 (`emacs-elisp-audit-findings.md`,
finding 1) pointed at `my/maintenance--set-keywords`: it rewrote a note
with `write-region` straight onto the file.  A write cut short -- a
full disk, a crash, the power -- leaves the note truncated.  The same
pattern was in six more places that rewrite notes from a temporary
buffer.  Git and the btrfs snapshots would bring a note back, but only
once the loss is noticed.

### What

- 000-core.el: `my/write-region-atomically` (section FILE HANDLING):
  the current buffer to a temporary file `.mypks-write-XXXXXX` in the
  note's folder, flushed to disk (`write-region-inhibit-fsync` nil), the
  note's permissions copied, then `rename-file` over the note.  On any
  failure the temporary file is removed and the note is as it was.  A
  symbolic link is written through to its target.
- Used instead of `write-region` in every place that rewrites a note:

  fix in the module the review named: the owner's rule is to fix a bug

## Session 2026-11-13a — Weekly check: declaration of citar-select-ref

### Why

The weekly run on GitHub (Emacs 30.2 and 31.1) failed since 2026-11-03c:
"declarations: 1 problem(s)", "417d-zotero-annotations.el:
citar-select-ref declared in citar.el: arglist mismatch".  The module
declared `(&rest args)`; citar defines the function with `cl-defun` as
`(&key filter)`.

### What

- 417d-zotero-annotations.el: `citar-select-ref` declared with argument
  list `t` (unspecified), with a comment on why.

### Decisions

- `t`, not the real `(&key filter)`: with that list check-declare is
  satisfied, but the byte compiler reads `&key` and `filter` as two
  required arguments and warns that the call `(citar-select-ref)`
  passes none.  `t` is the documented way to leave a declaration's
  arguments unchecked, and the only one both checks accept.  Not an
  entry in tests/weekly/declare-exceptions.txt: that list is for
  definitions check-declare cannot see, and this one it sees.

### Tested

`hooks/check-weekly`, run locally with citar installed: declarations 0
problems; 127 tests as expected; 417d-zotero-annotations compiles
without warnings.  (The other compile warnings of that local run come
from packages not installed there and appear on main alike; the
GitHub run installs every package.)

### Lessons learned

- `hooks/check-all` and the pre-commit hook do not run check-declare;
  only `hooks/check-weekly` does, because it needs every package
  installed.  A patch that adds a `declare-function` for a package's
  function is checked with `bash hooks/check-weekly declarations`
  before it is delivered.
- A function defined with `cl-defun` and keyword arguments cannot be
  declared with its real argument list: check-declare wants it, the
  byte compiler misreads it.  Declare such functions with `t`.

### Why

## Session 2026-11-03c — Zotero's annotations into a note (C-c x a)

### Why

Highlights made in Zotero's reader reached Emacs only through Readwise
(Zotero → zotero2readwise on altair → Readwise → 424-readwise.el),
hours late and outside the notes.  Zotero 10 serves its library on
localhost (the local API), so a note can take the annotations of its
book directly, with page numbers and a link back to the passage.

### What

- New module `417d-zotero-annotations.el` (optional, off on a new
  machine; requires 417-bibliography and 417c-zotero).
  `my/zotero-annotations-insert`, `C-c x a`: in an Org note, the
  annotations of the PDF or EPUB of the note's `#+reference` (citar
  when the note has none), each a quote, a `zotero:` link named after
  its page label and the comment; only annotations whose key is not yet
  linked in the buffer.  Options in the bibliography's settings: the
  API address, the page format, colours left out, joining words broken
  at line ends.  The `zotero:` link type opens through `browse-url`.
- init.el, MODULES.org, the ownership map in CHANGELOG.md:
  the module after 417c-zotero.
- function_helper.org: the menu row `a` and the section
  "a — Zotero's annotations into the note" (`#zotero-annotations`).
- TESTPLAN.org: R57.
- tests/test-zotero-annotations.el: ten tests, the local API and citar
  stood in for.

### Decisions

- Local API, read only.  Not zotero.sqlite: Zotero 10 runs it in WAL
  mode and its developer notes advise against reading it from outside.
  Not the Web API: a key, the network, and the state of the last sync.
  Writing annotations back (possible since Zotero 10: a highlight
  created through the local API on 2026-11-03 appeared in the reader)
  is a later, separate step: pdf-tools' coordinates have to be turned
  into Zotero's `annotationPosition`.
- The annotations are found through `?itemType=annotation` filtered by
  `parentItem`.  `GET .../items/<attachment>/children` answered with an
  empty list for an attachment with 103 annotations (Zotero 10.0.2,
  tried by the owner); the list of all annotations is one local
  request per command.
- The attachment key is the name of the file's folder in Zotero's
  attachments folder: no lookup by citation key, which would need
  Better BibTeX's field in the item data.
- Inserted at point, not into a fixed heading: a note's structure is
  the owner's.  Keys in the links make a second run add only what is
  new; nothing is ever removed from the note.
- Words broken at line ends ("indywidual- nego") are joined by default:
  Zotero returns the text as the PDF lays it out.  Upper case after
  the hyphen is not joined ("Kraków- Warszawa"); a suspended hyphen
  before a lower-case word is, and the option turns joining off.

### Tested

`tests/test-zotero-annotations.el`: 10 tests pass (Emacs 31.1, the
packages of tests/ci-packages.el plus citar and citar-denote).  The
module byte-compiles without warnings.  `hooks/lint.py`: all checks
pass.  Against the real Zotero: TESTPLAN.org R57.

### Lessons learned

- `string-match` and `replace-regexp-in-string` follow
  `case-fold-search`, which is on by default: `[A-Z0-9]` matched the
  lower-case folder "j27dmsmh" and `[[:lower:]]` upper-case letters
  until the functions bound it to nil.  A test with a lower-case
  folder name caught it.

## Session 2026-11-03a — Quoted phrases are wrapped inside the quotes

### Why

The owner reported that wrapping a second quoted phrase in a paragraph
with = or ~ seemed to reach back to the first wrapped phrase: the
words between the two phrases were shown as verbatim too.  The buffer
text was right -- `="first"=, text ="second"=` -- and the Org parser,
so export, read two separate spans.  Only the highlighting was wrong.
Org's PRE characters (`org-emphasis-regexp-components`) include the
double quote, so `org-do-emphasis-faces`, which steps back one
character after each match, read the first closing marker, standing
right after a quote, as an opening one whenever a non-space character
followed it; the span then ran to the second phrase's closing marker.
With `org-hide-emphasis-markers` on it looked as if the marker had
moved.  Reproduced in Org 9.6.15 and 9.8.10, with markers typed by hand
as well, and with `*` too.

The owner chose to move the markers inside the quotes.  A closing
marker after the last character of a phrase -- a letter, a full stop,
a question mark -- is not one Org reads as an opening marker.

Rejected: patching Org's highlighting (an override of
`org-do-emphasis-faces` for a display fault, far more code and a
maintenance burden at every Org release); keeping the old form (the
fault shows wherever a comma or full stop follows a phrase, which in
prose is most of the time).

Found on the way: a trigger typed right after an opening quote --
`"=` to write markup inside quotes by hand, `electric-pair-mode`
having added the closing quote -- took that quote for a closing one
and wrapped the text since the previous quote in the paragraph.

### What

- 302b-bold-marker.el: a trigger after a closing quote wraps the text
  between the quotes, `"*phrase*"`; point stays after the closing
  quote (`my/inline-marker--wrap` takes an optional RESUME marker).
  `my/inline-marker--quote-inner` returns the bounds inside the quotes,
  whitespace after the opening quote left out, nil for empty quotes.
  `my/inline-marker--closing-quote-p`: a quote preceded by whitespace
  or standing at the start of the line opens a phrase, and a trigger
  after it wraps nothing.  The already-wrapped check looks for the
  marker after the opening quote instead of before it.  Header and
  docstrings rewritten.
- tests/test-bold-marker.el: `my/bm-test-quoted-phrase-wrapped`
  rewritten for the new form; new
  `my/bm-test-two-phrases-in-a-paragraph` (the reported case, checked
  through Org's own font-lock: the text between the phrases has no
  verbatim face), `my/bm-test-phrase-whitespace-and-empty-quotes`,
  `my/bm-test-trigger-after-opening-quote-wraps-nothing`,
  `my/bm-test-expand-backward-from-phrase`.
- function_helper.org, /Inline Emphasis Markers/: the phrase rule, why
  inside, opening quotes, C-= after a phrase.

### Limits

- A phrase ending in `-`, `(`, `'` or `{` can still show the fault:
  those are the other PRE characters.
- A phrase ending in a space before its closing quote is not wrapped:
  that quote counts as an opening one.  The typed character stays.
- C-= after a phrase takes the opening quote into the span and leaves
  the closing quote outside; taking both in would bring the fault back.
- Notes written before this change keep the old form and display it
  wrongly where punctuation follows the first phrase.  No conversion
  was written; a one-off command with a dry run can be added if
  wanted.
- In export, the quotes are now plain text next to the span, so they
  become typographic where `org-export-smart-quotes-alist` has an entry
  for the note's language (Org has none for Polish; the repo adds
  none).  Inside a verbatim or code span they were always straight.

### Tested

`tests/test-bold-marker.el`: 12 of 12 (Emacs 29.3, Org 9.6.15).  Shown
to fail: with the module as before, five tests fail -- the four on the
phrase form and the opening-quote one.  The font-lock check reproduced
the fault with Org 9.8.10 from GNU ELPA as well.
