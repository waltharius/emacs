* Fonts as configuration, per silo
Proposed 2026-10-12, after the journal PDF export broke on font lookup.
Today the screen fonts are in =03b-fonts.el= (=my/font-silo-styles=, by
folder name) and the PDF font is one string, =my/latex-journal-font=.
Goal: one font setting per silo in the registry, used for both the
screen face and the PDF, taken (a) from the system by family name or
(b) from files in a directory the user names.  For PDF, prefer file
names over the family: the same family installed several times (static
and variable builds) makes luaotfload's choice unpredictable.  On the
NixOS side, one source for each font (the Nix package, or the files in
the repository) rather than several.

* Obsidian vaults
Proposed 2026-10-12.  Someone coming from Obsidian has Markdown notes

Options, not decided:

  =obsidian.el= (licht1stein/obsidian.el, MELPA, 2.0.0), which handles
  vaults, wikilinks, tags and backlinks in Emacs.  The registry would
  need a =:format= (=org= / =markdown=) or =:kind= (=denote= /
  =vault=) property, and modules that assume Denote file names must
  skip such a silo.
- *=my-notes-dir= itself as a vault*: one silo, sub-folders as the
  structure.

** TODO Automatic git without blocking (P1, P2, X5, X6, X10)
*Why*: the pull at start-up and every idle cycle run =git= with
=call-process=: Emacs freezes for the network round trip, up to the
5 s SSH timeout per repository when offline -- with writing projects and
the planner, several of them.  *Why later*: the largest change of the
review, and it touches the exit path, where losing a commit is worse
than waiting.  *How*: =make-process= with a sentinel chain (add →
commit → pull --rebase → push), one repository after another, as
=39-project-git.el= and =46-blog.el= already do; the synchronous path
kept for =kill-emacs-hook= only; the start-up pull asynchronous, buffers
reverted by =global-auto-revert-mode= when it lands.  At the same time:
=process-lines= instead of the remaining shell strings (=git status=,
=rev-list | grep=, =rev-parse=), =condition-case= with =display-warning=
instead of =ignore-errors= around commit, save and push, and one exit
path instead of three (=kill-emacs-hook=, =delete-frame-functions=, the
=save-buffers-kill-emacs= advice -- the advice runs before the "save
buffers?" question, which is why it exists; check before removing).

** TODO Start-up: early-init.el, compilation, lazy loading (S1-S3, B3, B4, P3, P4, P6, P7)
*Why*: about 30 000 lines read as source on every start, every theme
pack loaded to be available, 12 =:demand= and 109 top-level
=require='s.  *Why later*: belongs with the module loader (step 5),
which rewrites =init.el=; and every step needs measuring, not guessing.
*How*: =early-init.el= with the GC threshold, =package-enable-at-startup
nil= and =load-prefer-newer t=; =package-initialize= then stays where it
is (B4); modules on =load-path= and =require='d; native or byte
compilation as a =make= target, the pre-commit hook only checking that
it compiles.  Lazy loading one module at a time, each measured with
=M-x use-package-report= (statistics are on) and =emacs-init-time=
(TESTPLAN Preparation has the baseline): unused theme packs without
=:demand=, =:defer=/=:commands= for consult, citar, pdf-tools, nov,
denote-explore, keyfreq.  =use-package-always-ensure= (B3): every
built-in needs =:ensure nil=; a test on the clean-config branch catches
a forgotten one.  =use-package-compute-statistics= off once done (P6).
