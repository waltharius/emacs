** TODO 5. Module toggles (plugin loader)
An option listing optional modules to load, with descriptions and
declared dependencies; =init.el= loads the core always and the rest
from the list.  Turning a module off takes effect after a restart.
Toward a plugin contract: own group under an area, options applied with
=my/settings-apply-on-set=, =my/transient-append=, =provide=,
dependencies checked with =fboundp=.  The loader is the moment for the
review's start-up findings, since it rewrites =init.el= anyway: see
/Code review 2026-10-14/, items on start-up and on names.

Asked again 2026-10-16, with the shape wanted: a menu entry to turn
modules on and off -- at least the integrations not everyone uses
(Obsidian import, Zotero/Citar, Readwise, Hugo blog, drill cards).
Each module registers itself: name, one-line description, the modules
it needs.  Turning off a module others need is refused, or offered
together with them ("Readwise is needed by X; turn both off?"); turning
one on turns on what it needs.  The registry also gives the
=function_helper.org= sections and the menus check something to
compare against.  Modules are meant to stand alone, so most entries
should list no dependency; the ones that do are worth knowing about.

*A module contract first* (asked 2026-10-16: "like Obsidian plugins").
The toggles need it, and so does anyone writing a module of their own.
Models: Obsidian's =manifest.json= plus its submission requirements,
Spacemacs layers (=layers.el= declares the layers a layer needs), Doom
modules (=:depends=, =modulep!=).  Proposed shape, Emacs's own
conventions rather than a new format:
- *Manifest = library headers*, read without loading the file by
  =lisp-mnt= (=lm-summary=, =lm-header=): the first line's summary is
  the description; =;; MyPKS-Requires: 04-denote 05-notes= the modules
  needed; =;; MyPKS-Optional: yes= marks a module that may be turned
  off; =;; Package-Requires:= the external packages, as in any Emacs
  package.  The menu can then list modules that are off.
- *Rules*, each checked by a lint check =modules=: =provide= named
  after the file; options in an own group under one of the =mypks-=
  areas, applied with =my/settings-apply-on-set=; menu entries only
  through =my/transient-append=; contributions to shared lists
  (auto-commit sources, agenda files) through their hooks, never by
  editing another module; a =function_helper.org= section with
  =CUSTOM_ID=; nothing done at load beyond definitions.
- *On and off*: what a module does when on (hooks, timers, keys, menu
  entries) is started by a global minor mode, =my/<module>-mode=, and
  undone when the mode is turned off -- Obsidian's =onload=/=onunload=.
  Turning off then works without a restart; =unload-feature= is not
  relied on.
- *Own modules* in a =modules/= folder of the settings folder, loaded
  after the configuration's own, so a module can be added without
  touching this repository.

*Done 2026-10-16c*: the contract, the check =modules= and the headers
in all modules (function_helper.org, /Module contract/).  19 modules
are core, 33 optional.  =Package-Requires= left out: =use-package
:ensure= installs the packages, and a second list would drift from it.

* A public repository, without personal data
Asked 2026-10-14: this repository private, a second one public with the
code only, for anyone to start from a clean configuration.  Settled:
each machine's settings in =hosts/<host>/= of a settings folder outside
the repository (2026-10-14l, 2026-10-15a).

*Decided 2026-10-15: the data apart from the code, so that nothing has
to be synchronised.*  Two repositories with the same code and different
personal parts would need every change carried across and cleaned on
the way.  Instead:

- *Public repository* =~/.emacs.d=: the code and the documentation,
  generic.  The only one developed in.
- *The settings folder* (=~/.config/mypks/= by default, a setting;
  2026-10-15a): the settings of each machine.  Outside the code
  repository, so no =.gitignore= rule stands between private files and a
  push.  Here it goes into the notes repository (=~/notes/.mypks/=),
  which is private, on both machines and pushed automatically -- no
  third repository.
- A new machine: =git clone <public> ~/.emacs.d=, the notes as now, and
  /Folder of these settings/ set once.  Someone else: the clone only;
  the first start creates their =~/.config/mypks/hosts/<host>/=.

Rejected: =hosts/= as a private repository nested in =~/.emacs.d= and
ignored by it -- one wrong =.gitignore= line or a =git add hosts/= and
the private files are in the public repository.

* Polish for non-technical users
Asked 2026-10-15: someone weak in technical English may want to use
this configuration.  Emacs has no localisation of documentation
strings or Customize labels, so this is built, not switched on.

In order of use for the effort:
1. *A user guide in Polish* (=docs/pl/=, Org), task-oriented: how to
   write a note, find one, link, capture, plan, export.  Separate from
   function_helper.org, which explains the code; the guide explains the
   work and names keys and menu entries only.  Most of the value, no
   code.
2. *A catalogue of interface strings*: menu labels, prompts, messages
   and Customize tags/documentation read from one file per language,
   chosen by an option (=my/interface-language=).  Format: gettext
   =.po=, so the translation can be done in Poedit or a web tool
   without touching Emacs Lisp.  Transient labels and prompts call a
   lookup function; Customize documentation is replaced at load
   (=variable-documentation= property), tags likewise.  Every module
   touched, so in parts, starting with the main menu.
3. *A plain English guide* derived from the Polish one, for users who
   find function_helper.org too technical.

The guide (1) can start at any time; the catalogue (2) after the names
are settled (code review item B1), or every string key is renamed twice.

* Fonts as configuration, per silo
Proposed 2026-10-12, after the journal PDF export broke on font lookup.
Today the screen fonts are in =03b-fonts.el= (=my/font-silo-styles=, by
folder name) and the PDF font is one string, =my/latex-journal-font=.
Goal: one font setting per silo in the registry, used for both the
screen face and the PDF, taken (a) from the system by family name or
(b) from files in a directory the user names.  For PDF, prefer file
names over the family: the same family installed several times (static
and variable builds) makes luaotfload's choice unpredictable.  On the
NixOS side, one source for each font (the Nix package, or the files in
the repository) rather than several.

** TODO Automatic git without blocking (P1, P2, X5, X6, X10)
*Why*: the pull at start-up and every idle cycle run =git= with
=call-process=: Emacs freezes for the network round trip, up to the
5 s SSH timeout per repository when offline -- with writing projects and
the planner, several of them.  *Why later*: the largest change of the
review, and it touches the exit path, where losing a commit is worse
than waiting.  *How*: =make-process= with a sentinel chain (add →
commit → pull --rebase → push), one repository after another, as
=39-project-git.el= and =46-blog.el= already do; the synchronous path
kept for =kill-emacs-hook= only; the start-up pull asynchronous, buffers
reverted by =global-auto-revert-mode= when it lands.  At the same time:
=process-lines= instead of the remaining shell strings (=git status=,
=rev-list | grep=, =rev-parse=), =condition-case= with =display-warning=
instead of =ignore-errors= around commit, save and push, and one exit
path instead of three (=kill-emacs-hook=, =delete-frame-functions=, the
=save-buffers-kill-emacs= advice -- the advice runs before the "save
buffers?" question, which is why it exists; check before removing).
