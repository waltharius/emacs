Asked again 2026-10-16, with the shape wanted: a menu entry to turn
modules on and off -- at least the integrations not everyone uses
(Obsidian import, Zotero/Citar, Readwise, Hugo blog, drill cards).
Each module registers itself: name, one-line description, the modules

*A module contract first* (asked 2026-10-16: "like Obsidian plugins").
The toggles need it, and so does anyone writing a module of their own.
Models: Obsidian's =manifest.json= plus its submission requirements,
Spacemacs layers (=layers.el= declares the layers a layer needs), Doom
modules (=:depends=, =modulep!=).  Proposed shape, Emacs's own
conventions rather than a new format:
- *Manifest = library headers*, read without loading the file by
  =lisp-mnt= (=lm-summary=, =lm-header=): the first line's summary is
  the description; =;; MyPKS-Requires: 04-denote 05-notes= the modules
  needed; =;; MyPKS-Optional: yes= marks a module that may be turned
  off; =;; Package-Requires:= the external packages, as in any Emacs
  package.  The menu can then list modules that are off.
- *Rules*, each checked by a lint check =modules=: =provide= named
  after the file; options in an own group under one of the =mypks-=
  areas, applied with =my/settings-apply-on-set=; menu entries only
  through =my/transient-append=; contributions to shared lists
  (auto-commit sources, agenda files) through their hooks, never by
  editing another module; a =function_helper.org= section with
  =CUSTOM_ID=; nothing done at load beyond definitions.
- *On and off*: what a module does when on (hooks, timers, keys, menu
  entries) is started by a global minor mode, =my/<module>-mode=, and
  undone when the mode is turned off -- Obsidian's =onload=/=onunload=.
  Turning off then works without a restart; =unload-feature= is not
  relied on.
- *Own modules* in a =modules/= folder of the settings folder, loaded
  after the configuration's own, so a module can be added without
  touching this repository.

* Files the modules write: out of the code repository
Asked 2026-10-16: =recentf= and the keylog file =keys= belong in the
private settings folder, not in =~/.emacs.d= -- even ignored by git
they are personal, and per machine.  In general, every module has to
say what it writes besides code, so that it can live outside the
repository, differ between machines, or exist in several variants
(one per role).

Today, written into =~/.emacs.d= and kept out of git only by
=.gitignore=: =recentf=, =saveplace=, =bookmarks=, =savehist=/=history=,
=desktop/=, =.org-id-locations=, =org-clock-save.el=, =keys= (keylog,
14-typing-analytics.el), =.emacs.keyfreq=, =transient/= (menu
history), =persist/= (org-drill's learning data), =undo-fu-session/=
(text of edited buffers), =tramp=, =url/=, =eshell/=, =notes-root.eld=.

Proposal:
- *no-littering* (github.com/emacscollective/no-littering, on MELPA),
  the established package for this: it moves the files of Emacs and of
  many packages into two folders, =etc/= (configuration) and =var/=
  (state).  =no-littering-var-directory= pointed at
  =hosts/<host>/var/= of the settings folder, so that history,
  sessions and positions stay per machine and per role.  Both
  variables have to be set before the package loads, so early in
  00-core.el; its own README adds both folders to =recentf-exclude=.
- Three kinds of file, each with one helper in 00-core.el, used by
  every module instead of =user-emacs-directory=:
  - /settings/ (=custom.el=): already per machine;
  - /state of this machine/ (keylog, recent settings, notes root):
    =hosts/<host>/var/=;
  - /data shared by all machines/ (favourite settings, drill learning
    data?): the root of the settings folder.
- Module contract, a rule and a check: no module writes under
  =user-emacs-directory=; the header gains a line naming what the
  module writes (=;; MyPKS-Writes: var/keys=), so that the toggles menu
  and the README can list it.
- Moving existing files once, at the first start, as the settings were
  moved (2026-10-15a), with a report.

Order: after the decoupling, before the loader -- the loader's list of
modules turned off is itself a setting.

*Done 2026-10-18a*, the first file of the third kind: the personal

* Fonts as configuration, per silo
Proposed 2026-10-12, after the journal PDF export broke on font lookup.
Today the screen fonts are in =03b-fonts.el= (=my/font-silo-styles=, by
folder name) and the PDF font is one string, =my/latex-journal-font=.
Goal: one font setting per silo in the registry, used for both the
screen face and the PDF, taken (a) from the system by family name or
(b) from files in a directory the user names.  For PDF, prefer file
names over the family: the same family installed several times (static
and variable builds) makes luaotfload's choice unpredictable.  On the
NixOS side, one source for each font (the Nix package, or the files in
the repository) rather than several.
